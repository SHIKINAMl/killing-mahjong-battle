# プロジェクト固有のUI描画ルール (Unity UI Sorting)

## Nested Canvas における UI の最前面化について
特定の UI パネル（例: ツールチップ、スマホ型UIなど）を他のUIや3Dオブジェクトよりも手前に（最前面に）表示したい場合、以下のルールに従うこと。

1. **親Canvasの制限に注意する**
   特定のUIの `Canvas` コンポーネントだけ `overrideSorting = true` に設定しても、その大元となる親のCanvas（World Space や低い Sorting Order のCanvas）の設定に影響され、最前面に出られないことがある（Zバッファなどの影響を受けるため）。
   
2. **ルートとなる親Canvasの Order を引き上げる**
   UIを最前面に出すには、対象のUIだけでなく、**そのUIが属する大元のパネル全体のルートCanvas**の `overrideSorting` を有効にし、`sortingLayerName` や `sortingOrder` を適切な値（例: 20 など）に引き上げるのが効果的である。

3. **内部の子Canvasを一律で上書きしない（重要！）**
   親UIの Canvas の Order を引き上げる際、**絶対に `GetComponentsInChildren<Canvas>(true)` を使って全ての子要素の Canvas の Order を一律で上書きしてはならない**。
   一律で上書きしてしまうと、UI内部の前後関係（背景画像とボタンの重なりなど）が壊れ、「背景が手前に来てボタンが隠れてしまう（ボタンが消えたように見える）」といった致命的なバグが発生する。
   **必ずルートのCanvasのみを設定し、子要素の順序はそのまま保つこと**。

# Pythonコードの編集禁止ルール
killingmahjongbattle プロジェクトにおける **Python側のコード**（サーバー側など）は他の開発者が担当・記述した部分であるため、AIエージェントが**絶対に修正・変更・上書きをしてはならない**。
Unity側（C#やアセット）の改修のみに専念すること。

# オブジェクトプールとUI要素の親子関係に関するルール
「オブジェクトプール」を利用して使い回すUI要素（例：麻雀牌のプレハブなど）に対して、**外部のUIオブジェクト（カーソル、矢印、Waitアイコンなど）を一時的に子オブジェクトとして `SetParent` で追加してはならない。**
- 理由: プールに回収される際に外部オブジェクトがくっついたまま一緒に回収されてしまい（プール汚染）、次にそのオブジェクトが再利用された際に意図しない画像（例: 待ち牌の矢印など）が勝手に表示され続けるバグの原因となるため。
- 対策: 外部から追従させたいUI要素は、プーリングされる対象（牌）の子にするのではなく、**同じ階層のコンテナ（例: WallContainerなど）の子にした上で、毎フレーム座標を合わせる**か、**表示時に位置を計算して配置する**設計にすること。

# 手牌と山牌のUIコンテナに関するルール
- 手牌（HandUI）は、手牌フェイズ用と打牌フェイズ用の2つのコンテナが別々に存在し、フェイズが切り替わるたびにコンテナを行き来して表示される。
- 山牌（WallUI）は、1つのコンテナしか存在せず、手牌フェイズと打牌フェイズで**コンテナ自体の位置（座標）が移動する**仕様となっている。
- そのため、手牌フェイズなのに打牌フェイズのコンテナ（左下など）に牌が表示されている場合は、`PhaseController.HandlePhaseVisibility` などのフェイズ遷移が正しく同期していないか、手牌と山牌のコンテナ設定を誤解して配置している可能性を疑うこと。
